# Music Big Data v2 — crawler / ingestion starter

Scope aligned to the project: collect music trend signals from Zing MP3, Spotify, Apple Music, YouTube and Google Trends; normalize them; keep long-term history; and produce realtime `play` / `like` / `skip` events for a Lambda-style Big Data pipeline.

## Recommended acquisition strategy

- **Apple Music**: official Apple Music API `/v1/catalog/{storefront}/charts`, `chart=most-played`, `storefront=vn`.
- **YouTube**: official YouTube Data API `videos.list(chart=mostPopular, regionCode=VN, videoCategoryId=10)` plus comment threads. Comments do **not** contain reliable commenter province; treat them as text/engagement signals, not true geolocation.
- **Spotify**: use Spotify Charts export for platform-level trend snapshots; use Web API only for consented user listening history. Current Web API is not a general regional-charts API.
- **Google Trends**: prefer official Trends API when your team gets alpha access. `google_trends_pytrends.py` is only a fallback because pytrends is unofficial and can be rate-limited/broken.
- **Zing MP3**: no stable documented public developer chart API is assumed. Store/normalize a permitted public chart JSON/browser export. Do not make a private signed reverse API a critical dependency.

## Quick start (One-Click Pipeline)

```bash
# Setup virtual environment with uv:
uv venv .venv
source .venv/bin/activate
uv pip install -r requirements.txt

# Run the complete end-to-end ingestion and processing pipeline:
python run_all.py
```

### Individual Crawlers & Pipeline Modules

```bash
# Apple Music (uses official token if set, otherwise falls back to public RSS feed)
python crawlers/apple_music_charts.py --storefront vn --limit 50

# Zing MP3 (auto-fetches online chart or reads input/zing_chart.json)
python crawlers/zing_chart_unofficial.py

# Spotify Charts (reads input/spotify_vn.csv)
python crawlers/spotify_chart_csv.py

# YouTube Trending Music & Comments (uses API key if set, or curated dataset)
python crawlers/youtube.py --region VN --limit 20 --comments-per-video 5

# Google Trends Subregion Interest (auto-extracts keywords from top charts)
python crawlers/google_trends_pytrends.py

# Realtime synthetic app events (stream to Kafka or save to JSONL)
python crawlers/system_event_producer.py --out-file output/user_events.jsonl --max-events 200

# Entity Resolution: Canonical track clustering across platforms
python pipeline/entity_resolution.py

# Province Interest Estimation: Trends + Comment text signal + User events
python pipeline/province_interest.py
```

All raw & processed outputs are written in JSONL format to `output/`:
- `output/apple_music_chart_vn.jsonl`
- `output/zing_chart_vn.jsonl`
- `output/spotify_chart_VN.jsonl`
- `output/youtube_VN.jsonl`
- `output/google_trends_regions.jsonl`
- `output/user_events.jsonl`
- `output/canonical_tracks.jsonl`
- `output/province_interest.jsonl`

## Critical modeling rule

`province_interest` is an **estimated interest signal**, not platform-published play counts. It may combine Google Trends subregion interest, province mentions/text signals in comments, and geolocated events generated by your own system. Keep each component and its provenance so the dashboard can explain the estimate.

## Suggested Lambda data flow

Batch sources / snapshots -> object storage (Bronze) -> Spark batch normalization/entity resolution -> Silver/Gold tables -> recommender training / national & cross-platform analytics.

Realtime user events -> Kafka -> Flink/Spark Structured Streaming -> realtime counters / session features -> ClickHouse/Redis -> realtime reranker -> playlist after a few seconds.
